## Local Expo slice completed

- `expo/src/app/api/admin-ai+api.ts` verifies a Supabase user token, checks the current profile's admin role server-side, and reads only bounded experiment/run/job rows plus planned content counts. It uses a server-only `SUPABASE_SECRET_KEY` or `SUPABASE_SERVICE_ROLE_KEY`, returns no private credential, and marks responses private/no-store. Missing configuration fails closed.
- `expo/src/services/admin-ai.ts` passes the signed-in session token to the same-origin route. The Admin AI tab renders protected content estimates and recent ML evidence when available, and shows a configuration error otherwise. New copy is in EN/ES/TR.
- The existing admin workspace query now uses `quick_exams` for exam counts.
- Local authentication fixtures cover missing token, missing server config, non-admin denial, and admin success. TypeScript, targeted ESLint, and a 26-page server export with both API routes passed. The web client bundle contains no server credential variable name.

## Deployment boundary

The current local `.env.local` has public Supabase configuration and an AI provider key, but no server-only Supabase credential. EAS Hosting requires a server environment variable with **sensitive** visibility for this route, followed by a new immutable preview deployment. The Python services currently obtain the actor through Streamlit `st.session_state` and store ML artifacts under local `reports/` paths; no standalone Python API or durable worker deployment exists in this repository. Those are concrete blockers to launching experiments, rerunning integrity checks, or serving generated reports from the hosted Expo app today.

Next implementation order: provision the protected preview read and verify admin/non-admin access; introduce an explicit request-scoped actor context in a separately deployed Python API/worker; expose only approved ML launch, integrity, eligibility, and report operations with existing capability/audit controls; then connect Expo controls and verify one bounded staging run without broad data operations.
